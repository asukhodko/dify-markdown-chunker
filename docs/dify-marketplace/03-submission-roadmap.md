# План подготовки к публикации в Dify Marketplace
## Краткое резюме
В этом плане описаны шаги, необходимые для подготовки плагина `dify-markdown-chunker` к публикации в Dify Marketplace. По результатам gap-анализа, плагин **готов примерно на 85%** - основной функционал, тестирование и базовая документация на высоком уровне. Однако отсутствуют критически важные элементы для публикации (политика конфиденциальности, контактная информация, подача заявки).
**Расчётное время до завершения:** 2-3 дня
**Уровень риска:** Низкий (все пробелы связаны с документацией/процессом, а не с техническими аспектами)
## Классификация приоритетов
### 🔴 P0 - Блокеры (обязательно завершить перед подачей)
Эти пункты приведут к немедленному отклонению на этапе модерации.
### 🟡 P1 - Высокий приоритет (желательно завершить перед подачей)
Эти пункты значительно повышают шансы на одобрение и улучшают пользовательский опыт.
### 🟢 P2 - Улучшения (можно завершить после подачи)
Улучшения качества, которые можно реализовать после первоначального одобрения.

**Требования к содержанию:**
```markdown
# Политика конфиденциальности для Advanced Markdown Chunker
## Сбор данных
- **Персональные данные:** Не собираются. Плагин не собирает, не хранит и не передаёт персональные данные.
- **Обработка:** Весь Markdown-текст обрабатывается локально в среде выполнения Dify.
- **Хранение:** Данные не хранятся за пределами стандартных механизмов Dify.
## Использование данных
- Входной текст обрабатывается исключительно для генерации чанков документа
- Нет логирования пользовательского контента
- Нет обращений к внешним API и передачи данных
## Сторонние сервисы
- **Отсутствуют:** Плагин не интегрируется и не передаёт данные каким-либо внешним сервисам.
## Изменения в этой политике
Обновления будут публиковаться в репозитории и отражаться в релизах плагина.
## Контакты
По вопросам конфиденциальности: [контактная информация]
```
**Критерии приёмки:**
-  Файл `PRIVACY.md` существует в корне репозитория
-  Политика конфиденциальности охватывает все требуемые разделы согласно руководствам Dify
-  В `manifest.yaml` есть поле `privacy: PRIVACY.md`
-  Нет противоречий между политикой конфиденциальности и README

```markdown
## 🔄 Сравнение с другими Markdown chunker'ами
### vs. Простые text splitter'ы
Стандартные text splitter'ы (включая базовые Markdown chunker'ы) используют подсчёт символов/токенов без понимания структуры документа. Этот плагин использует полный AST-парсинг для сохранения семантических границ.
### vs. md-text-chunker
Оба плагина работают с Markdown, однако данный плагин предлагает:
| Функция | md-text-chunker | Advanced Markdown Chunker |
|---------|----------------|---------------------------|
| **Выбор стратегии** | Единый подход | 6 адаптивных стратегий (auto/code/structural/mixed/sentences/tables) |
| **Анализ контента** | Базовый | Глубокий AST-парсинг с оценкой сложности |
| **Работа с кодом** | Ограниченная | Полное сохранение блоков кода + определение языка |
| **Метаданные** | Базовые | Богатые метаданные (глубина структуры, тип контента, информация о перекрытии) |
| **Обработка таблиц** | Разбиение по размеру | Сохранение полных таблиц с заголовками |
| **Обработка списков** | Базовая | Умная стратегия списков с сохранением вложенности |
| **Тестирование** | Стандартное | 445 тестов включая property-based тестирование |
| **Fallback** | N/A | Graceful degradation с восстановлением после ошибок |
### Когда использовать каждый плагин
**Используйте этот плагин, когда:**
- Обрабатываете техническую документацию с большим количеством примеров кода
- Сложные документы с глубокой иерархией заголовков
- Нужен детальный контроль над стратегией чанкования
- Требуются подробные метаданные чанков для отладки
- Нужен автоматический выбор стратегии на основе контента
**Используйте более простые chunker'ы, когда:**
- Простые текстовые документы без структуры
- Производительность критичнее качества
- Нужна минимальная конфигурация
```
**Критерии приёмки:**

-  Включает рекомендации, когда использовать каждый подход

```markdown
## Подача плагина: Advanced Markdown Chunker
### Обзор
Продвинутый плагин для чанкования Markdown со структурной осознанностью и адаптивным выбором стратегии для улучшения производительности RAG.
### Обоснование уникальности
Я знаю о существующем плагине `md-text-chunker`. Данная подача представляет фундаментально другой подход:
**Архитектурные отличия:**
1. **Полный AST-парсинг:** Использует полное синтаксическое дерево Markdown vs. парсинг на основе регулярных выражений

4. **Сохранение структуры:** Поддерживает иерархию заголовков, блоки кода, таблицы как атомарные единицы
**Почему отдельный плагин:**
- Другой алгоритмический подход (AST vs. простое разбиение)
- Ориентирован на другие use case'ы (сложная техническая документация vs. общий текст)
- Компромисс: Более высокое качество чанков за счёт немного большей обработки
- Не форк и не минорная модификация - полностью независимая кодовая база
**Ценность для пользователей:**
- Решает проблемы качества RAG с документацией, насыщенной кодом
- Предоставляет детальный контроль для продвинутых пользователей
- Сохраняет обратную совместимость через множественные варианты стратегий
```
